# 阶段 7.3：AI 行程草稿与严格校验

## 这一阶段解决什么

用户填写目的地、天数、出发日期、预算和偏好后，可以请求 AI 生成一份候选行程。它只是可编辑草稿，不代表已经保存，更不会自动预订任何服务。

新增接口：`POST /api/v1/trips/generate`。

## 通俗流程

1. 后端把用户要求与专用提示词交给统一 LLM Client，不绕过额度、日志和异常处理。
2. 模型只返回标题、每日安排和单项费用，不允许返回总预算或余额。
3. 后端用 Pydantic 和业务代码再次检查：天数完全一致、日期从 1 连续递增、每天 1～8 项、同一天时间严格升序、金额非负且最多两位小数。
4. 校验失败会把纠正要求追加到对话并重试一次；第二次仍失败则返回 `50202`，提示用户手动创建或稍后重试。
5. 合法结果将元精确转换为整数分，由代码重算预计花费、预算余额和是否超支，标记为 `generated_by=ai`、`status=draft`。
6. 整个生成接口不接收数据库 Session，也不新增 `Trip` 或 `TripItem`。只有用户之后确认并调用创建行程接口，草稿才会保存。

提示词还明确把用户偏好当作不可信资料，禁止模型执行其中的指令；行程中的景点、营业时间与价格仍需出行前核实。

## 涉及文件

- `backend/app/modules/trip/ai_service.py`：模型调用、纠错重试、业务校验、金额与预算计算。
- `backend/app/modules/trip/schemas.py`：模型 JSON 输出和草稿响应结构。
- `backend/app/modules/trip/router.py`：静态 `/generate` 接口，放在 `/{trip_id}` 动态路由之前。
- `backend/app/llm/prompts/trip_generate.txt`：JSON 结构和旅行安全约束。
- `backend/tests/test_trip_ai_api.py`：使用 FakeLLMClient，不访问真实模型或网络。

## 验证与边界

旅行手动与 AI 共 17 项测试通过。其中 AI 覆盖合法草稿、两位小数元转分、排序位置、预算重算、非法 JSON 重试、天数错误、日期重复、空日程、时间倒序、金额超过两位小数、模型伪造总价、二次失败、认证与请求校验，并确认成功和失败均不写库。

这些测试验证的是程序约束，不代表真实模型生成内容已经过旅行质量验收；真实模型效果、景点信息准确性和浏览器交互仍需后续实际验收。
