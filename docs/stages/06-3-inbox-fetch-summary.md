# 阶段 6.3：安全抓取、AI 摘要与失败兜底

## 完整流程

保存链接后主事务立即提交并返回 `pending`，FastAPI `BackgroundTasks` 再启动独立数据库会话：

`pending → processing → 抓取正文 → 保存正文 → AI 摘要/标签 → success`

任一步失败都会记录 `failed` 与 `fail_reason`。已抓取或手动粘贴的正文不会因为 AI 失败而丢失。

## 安全与可靠性

- 仅 HTTP/HTTPS，不允许 URL 内嵌账号密码。
- 字面 IP 与 DNS 解析结果都必须是公网地址；拒绝 localhost、私网、回环、链路本地、保留地址及 IPv6 回环。
- 最多 3 次重定向，每个新目标重新执行完整校验。
- 连接、读取等超时均为 10 秒；响应最大 2MB，只处理 `text/html`。
- 使用 trafilatura 提取正文；正文截断到 8000 字后送模型。
- Prompt 明确网页资料不可信，模型无工具权限，只返回摘要与最多 5 个标签的 JSON。
- 非法 JSON、缺字段或类型错误会纠错重试一次，仍失败返回/记录 50202。

## 新增接口

- `POST /bookmarks/{id}/retry`：重新加入后台处理队列。
- `PUT /bookmarks/{id}/content`：保存手动正文并同步重新生成摘要。

## 可测试性

后台任务不复用请求级 Session，而是注入新的 session factory；抓取器与 LLM factory 同样可替换。测试环境把路由后台处理器替换为空操作，避免任何真实网络或模型调用，再直接对真实处理函数做内存库验收。

## 验证
