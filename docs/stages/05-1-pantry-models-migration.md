# 阶段 5.1：食材与购物清单数据基础

## 目标

建立食材管家的两张业务表，为后续入库、FEFO 扣减、临期查询和购物清单提供可靠的数据基础。

## 背景知识

- **批次**：每次买菜入库都是一条独立记录。同一食材可以有多个批次，每个批次有各自的保质期。
- **Decimal / NUMERIC**：食材可能出现 0.5 千克等数量，使用十进制定点数而不是二进制浮点数，减少累计误差。
- **FEFO**：先过期先使用。本任务先建立批次和保质期索引，下一个小任务实现扣减算法。

## 实现内容

- 新增 `backend/app/modules/pantry/models.py`：
  - `ingredients`：名称、数量、固定单位、过期日、购买日、存放方式、状态、备注。
  - `shopping_items`：名称、可选数量与单位、完成状态、来源、来源菜谱。
  - 两张表均包含用户归属、创建/更新时间和软删除字段。
- 数据约束：库存数量不得为负；购物数量存在时必须大于 0；单位、存放方式、库存状态和来源使用固定枚举。
- 复合索引：支持按用户和名称查批次、按状态查临期、按存放方式分组、按完成状态查购物清单。
- 新增 Alembic 迁移 `3496ad17416b_create_pantry_tables.py` 并应用到开发数据库。
- 测试公共装置注册食材模型，确保内存测试库覆盖新表。
