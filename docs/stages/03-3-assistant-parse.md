# 阶段 3.3：AI 工具定义与意图解析接口

## 这一步做什么

新增 `POST /api/v1/assistant/parse`。用户输入一句话后，系统调用统一 LLM Client 识别动作，并返回可编辑的候选动作。这个阶段**只理解和登记，不创建待办、日程、账目或其他业务数据**。

## 工具与参数校验

`app/llm/schemas.py` 登记了说明书要求的 8 种工具：新建待办、新建日程、记支出、记收入、添加食材、收藏链接、创建旅行计划、追问。

每个工具都有独立 Pydantic 模型，规则包括：

- 未登记字段直接拒绝，避免模型拼错字段后被静默忽略。
- 日期时间必须带时区，日程结束时间不得早于开始时间。
- 金额和数量必须为正数，金额最多两位小数。
- 食材单位、存放方式、优先级和旅行天数使用明确范围。
- 信息不足时只能返回 `ask_clarification`，不能与其他动作混用。

模型返回未知工具、缺少字段、类型错误或没有工具调用时，服务会附带纠错提示自动重试一次。第二次仍不合法，返回 HTTP 502 / 50202，并保存一条 `failed` 解析记录。

## Prompt 与时间上下文

意图 Prompt 独立放在 `app/llm/prompts/intent.txt`，文件头包含用途、版本和日期。每次解析会注入：

- 当前用户的本地时间（含 UTC 偏移）；
- 当前星期；
- 用户时区；
- 多动作、追问、金额单位、ISO 时间格式及提示注入防护规则。

“明天”“周五”等相对时间由模型根据这些上下文解析；后端负责校验格式，不盲目相信模型。后续修改 Prompt 后必须运行评测集，本任务的评测集将在后续小步补齐。

## 待确认记录

成功时写入 `assistant_records(status=pending)`：

- 单动作 `intent` 为工具名，多动作为 `multi_action`；
- `parsed_json` 保存校验后的工具、参数和摘要；
- 追问仍保存在记录中，但接口的 `actions` 为空，问题放在 `clarification`，因此不会出现可确认的追问动作。

展示摘要由后端根据已校验字段生成，不直接采用模型的自由文本。金额在 JSON 中仍是数字，确认执行时才精确换算为整数分。

## FakeLLMClient 与依赖注入

`app/llm/fake.py` 提供与真实客户端相同 `chat()` 签名的假客户端，按队列返回预设结果或异常，并记录消息和工具供测试断言。FastAPI 通过 `get_llm_client` 工厂获取真实客户端，测试覆盖该依赖即可，全程不访问外部模型。

## 验证结果

新增 7 个专项测试，覆盖：

- 日程解析、时间/星期/时区注入、记录持久化以及业务表零写入；
- 多动作和金额 JSON 数字；
- 信息不足追问；
- 首次非法、重试后成功；
- 两次非法后的 50202 与 failed 记录；
- 未登录和空白输入；
- 工具注册、额外字段、朴素时间和日程时间顺序校验。

完整后端回归 **226 项全部通过**，Ruff 检查与格式检查通过。
