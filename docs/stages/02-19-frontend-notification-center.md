# 阶段 2.19：前端提醒轮询与通知交互

## 这一步做什么

在登录后的所有页面右上角增加“通知”入口和未读角标。后端触发的新提醒会在轮询后出现，用户可以查看对应模块或标记已读。LIFE-07 的日程提醒链路至此完整接通。

## 新增内容

- `types/notification.ts`：通知与分页响应类型。
- `api/notifications.ts`：未读列表和标记已读封装。
- `NotificationCenter.vue`：角标、通知面板、轮询、查看和已读交互。
- `App.vue`：只在已登录且已恢复用户信息时挂载通知中心。

## 轮询是什么

轮询是浏览器每隔一段时间主动问一次后端“有没有新通知”。本阶段按说明书每 30 秒请求一次 `GET /notifications?unread=true`，不需要 WebSocket 或 SSE。

```text
登录 → 立即查询 → 每 30 秒查询 → 新通知更新角标 → 已读后从列表移除
```

## 交互与资源管理

- 首次成功加载只建立已知列表，不把所有历史未读当成新消息弹出。
- 后续出现新 ID 时显示一条新提醒提示。
- 页面隐藏时暂停定时请求，重新可见时立即刷新。
- 上一次请求未结束时跳过重复刷新，避免请求重叠。
- 轮询失败保留旧数据，不反复弹全局错误；面板内显示原因并可手动重试。
- 组件卸载或退出登录时清理定时器和页面可见性监听器。
- 已读成功后本地移除记录并减少角标，不必再等待下一轮请求。
