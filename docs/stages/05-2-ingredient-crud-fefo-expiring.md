# 阶段 5.2：食材库存、FEFO 扣减与临期接口

## 目标

让食材真正可以入库、编辑、删除、消耗，并按用户当地日期找出已经过期和即将过期的批次。

## 实现内容

- 新增 `POST /api/v1/ingredients`：每次调用创建独立批次，不合并同名食材。
- 新增 `GET /api/v1/ingredients`：分页，支持状态、存放方式、精确名称筛选；默认只看 active。
- 新增 `GET / PATCH / DELETE /api/v1/ingredients/{id}`：详情、局部更新、软删除；越权与不存在统一 404。
- 新增 `POST /api/v1/ingredients/consume`：按名称、单位和数量消耗。
- 新增 `GET /api/v1/ingredients/expiring`：默认 3 天，支持 0～365 天，分开返回 expired 和 expiring。

## FEFO 如何工作

1. 只选择当前用户、同名、同单位、active、未删除且数量大于 0 的批次。
2. 按过期日升序排列，无过期日的批次排最后，同一天再按入库顺序排列。
3. 先汇总可用库存；不足则返回 42201，以及 requested / available / shortage，扣减前不会改变任何批次。
4. 库存足够时依次扣减，批次数量到 0 自动改为 used_up，返回每个批次的扣减明细。
5. `commit=False` 允许后续“做了这道菜”把多次扣减放进同一个外层事务。

本期刻意不做克与千克等单位换算。单位不一致会拒绝，并在存在同名库存时提示现有单位。

## 临期口径

当前时间经 `now_utc()` 获取，再转换到用户时区得到“今天”。过期日早于今天属于 expired；今天到第 N 天属于 expiring。请求未传 days 时读取用户设置 `expiring_days`，无效或缺失时回退为 3。
