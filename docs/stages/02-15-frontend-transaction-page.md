# 阶段 2.15：记账列表与新建编辑页面

## 这一步做什么

把分类和账目 API 变成可操作的 `/transactions` 页面。现在可以按月份、收支和分类查账，手动记一笔，修改历史记录，或经过确认后软删除。

## 页面与组件

- `TransactionView.vue`：页面编排、筛选、分页、删除和错误状态。
- `TransactionFilters.vue`：月份、类型、分类、排序字段和方向。
- `TransactionFormDialog.vue`：新建与编辑共用的表单。
- `TransactionList.vue`：账目卡片、分类摘要、发生时间和来源。
- `MoneyText.vue`：统一金额符号、颜色和千分位展示。

按说明书的工程约定拆分组件，避免把表单、筛选、列表和页面请求全部塞进一个超长文件。

## 涉及的知识

- **受控表单**：编辑时把账目复制到表单状态，取消不会直接修改列表对象。
- **计算属性**：可选分类随收支类型自动变化；切换类型后，如果原分类不匹配，会选择新类型的第一个分类。
- **前端校验与后端校验**：前端尽早提示金额格式、必填项，但最终仍由后端检查分类归属和类型匹配，不能只信任浏览器。
- **用户时区**：默认“本月”按用户时区计算；发生时间用 `Date.toISOString()` 转成 UTC 提交，展示时再转回用户时区。
- **软删除**：删除只是让记录不再出现在正常列表，数据库仍保留历史行。

## 金额处理示例

用户输入 `19.90`，`yuanToCents()` 提交 `1990`；后端返回 `1990` 后，`MoneyText` 显示 `-¥19.90`（支出）或 `+¥19.90`（收入）。格式不正确、为零或超过两位小数时不会发请求。

## 交互细节

- 新建成功后切换到新账目所在月份，避免记录被旧筛选条件隐藏。
- 编辑后保留当前筛选条件，记录是否仍显示由后端查询结果决定。
- 删除当前页最后一条时自动回上一页。
- 加载失败可重试；分类加载失败有独立提示，不会被误认为“没有账目”。
- 页面同时标出手动、AI、食材和旅行来源，后续模块写入的账目也能辨认。

## 如何验证

执行 `cd frontend && npm run build`，TypeScript/Vue 类型检查与生产构建通过，`TransactionView` 生成独立 JS/CSS 分包。

本阶段未引入浏览器 E2E，因此构建通过不代表自动联调已执行。手动验收时，应分别创建支出和收入，验证 `0.01`、两位小数、非法金额、类型切换、跨月查询、编辑、删除和分页。

分类管理入口将在紧接着的 2.16 接入对应页面。
