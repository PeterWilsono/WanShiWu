# 阶段 10.2：收藏网页读取与正文补救

## 先分清两层能力

收藏流程是“服务器抓取公开网页 → 提取正文 → AI 阅读正文并总结”。AI 不会主动打开链接。“未能提取正文”发生在前两层，并不代表模型不能总结文字。

## 自动读取改进

- 使用更完整的浏览器 Accept、语言和 User-Agent 请求头，减少公开网页的兼容性差异。
- 支持 `application/xhtml+xml` 和缺失 Content-Type 时的安全 HTML 嗅探。
- 识别 HTML meta 中的中文编码，增加 GB18030 解码兜底。
- Trafilatura 提高召回并保留表格；无法识别时，再从 `article/main/body` 提取文本，剔除脚本、导航、页脚等噪声。
- 401/403、404、超时和非 HTML 文件分别给出可操作提示，不再只显示笼统失败。
- 原有 SSRF、公网 IP、重定向、10 秒超时与 2MB 限制保持不变。

## 动态网页的诚实兜底

登录墙、验证码、付费内容和完全依赖浏览器 JavaScript 的页面，仍可能需要手动复制。正文对话框新增“打开原文并复制正文”和两种保存方式：

- **保存并生成摘要**：正文先落库，再调用 AI。
- **仅保存正文**：不调用模型，直接归档，稍后仍可补摘要。

## 验证

- 新增 XHTML 兜底、GB18030、无 Content-Type、403 提示、空网页异常和不调用 AI 的正文保存测试。
- 收藏相关 28 项测试通过，前端生产构建通过；最终后端全量 337 项测试通过。
- 未提供具体失败网址，因此不能宣称该网站已实测抓取成功；不会绕过登录或反爬限制。
