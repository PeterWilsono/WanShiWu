# 阶段 1.5：登录页、路由守卫与登录回跳

## 这一阶段在做什么

这一阶段把前面完成的后端认证 API、Axios 和 Pinia 接到真正的页面上：

- 新增 `/login` 登录页，支持表单校验、加载状态和错误提示。
- 首页 `/` 标记为需要登录，未登录访问会被送到登录页。
- 本地有 Token 时，通过 `/auth/me` 验证并恢复当前用户。
- 登录成功后返回原来想访问的页面。
- 已登录用户访问登录页时返回首页。
- 首页临时显示当前用户名和退出按钮，便于验证完整流程。

至此，阶段 1「骨架与登录」的前后端流程已经串起来。

## 主要文件

- `frontend/src/views/LoginView.vue`：登录表单、错误展示、登录提交与安全回跳。
- `frontend/src/router/index.ts`：登录页路由、路由 meta 和全局前置守卫。
- `frontend/src/types/router.d.ts`：为 `requiresAuth`、`guestOnly` 增加 TypeScript 类型。
- `frontend/src/views/HomeView.vue`：显示当前用户，提供退出登录入口。

## 用到的主要知识

### 1. SPA 路由与后端接口的区别

Vue Router 的 `/login`、`/` 是浏览器页面路径，由前端管理；`/api/v1/auth/login` 是后端数据接口。页面导航不一定重新加载整个应用，因此需要在路由跳转时检查登录状态，而不能只依赖页面刷新。

### 2. 路由 meta 是什么

`meta` 是挂在路由上的附加信息，本阶段定义：

- `requiresAuth: true`：必须登录才能访问。
- `guestOnly: true`：只给未登录用户使用，例如登录页。

以后新增页面时，只需在路由上声明 `requiresAuth`，守卫就能复用同一套检查逻辑，不必在每个页面组件里重复判断。

`router.d.ts` 是对 Vue Router 类型的扩展，让 TypeScript 认识这两个自定义字段。

### 3. 全局前置守卫

`router.beforeEach` 会在每次导航真正完成前执行。守卫可以允许导航，也可以返回另一个路由位置进行重定向。

受保护页面的判断顺序是：

```text
是否有 Token？
  ├─ 没有 → /login?redirect=原页面
  └─ 有 → 是否已有当前用户？
            ├─ 有 → 允许进入
            └─ 没有 → 请求 /auth/me
                        ├─ 成功 → 保存用户并允许进入
                        └─ 失败 → 清理 Token，去登录页
```

不能只凭 localStorage 里有 Token 就认为登录有效，因为 Token 可能过期、被篡改，或者对应用户已不存在。后端 `/auth/me` 才是最终确认。

### 4. 为什么已登录用户访问登录页还要验证 Token

本地可能残留过期 Token。如果只看 Token 是否存在，会把用户从登录页送回首页，首页再送回登录页，形成反复跳转。

因此 `guestOnly` 页面在已有 Token 但没有用户资料时，也会先验证 `/auth/me`。有效才送首页，无效则清理并留在登录页。

### 5. 登录后回跳与开放重定向

未登录访问 `/life` 时，登录地址会带：

```text
/login?redirect=/life
```

登录成功后读取 `redirect` 并返回 `/life`。

回跳目标只接受以单个 `/` 开头的站内路径，明确拒绝 `//example.com` 这类外部地址。即使跳转由前端路由处理，也应该对 URL 参数保持不信任，避免以后代码改动引入开放重定向问题。

### 6. 表单校验与加载状态

Element Plus 的 `FormRules` 在提交前检查必填字段，字段不合法时不会调用后端。

`authStore.loading` 绑定登录按钮的 loading 状态：请求期间按钮显示加载并防止重复提交。后端业务错误通过 `ApiError.message` 显示在表单顶部，网络未连接也会得到可理解的提示。

密码框使用 `show-password` 允许用户临时查看输入，浏览器自动填充字段分别使用 `username` 和 `current-password`。

### 7. 登录页懒加载

登录页使用动态导入：

```ts
component: () => import('../views/LoginView.vue')
```

Vite 会把它拆成独立文件，只有访问登录页时才下载对应页面代码。这是路由级代码分割的基础做法。

### 8. 退出登录

退出时清除 localStorage 和 Pinia 中的 Token、用户信息，再导航到登录页。JWT 本身有过期时间，当前个人项目没有服务端令牌黑名单；删除本地令牌后，浏览器后续请求就不会再携带它。

## 如何手动验证完整流程

1. 启动后端和前端。
2. 如果还没有账号，通过 `http://localhost:8000/docs` 的 `/api/v1/auth/register` 创建账号。
3. 打开 `http://localhost:5173/`，未登录时应跳到 `/login?redirect=/`。
4. 输入错误密码，应停留在登录页并显示「用户名或密码错误」。
5. 输入正确账号密码，应登录成功并返回首页，首页显示用户名。
6. 刷新页面，应通过 Token + `/auth/me` 恢复用户，不需要重新登录。
7. 点击退出登录，应回到登录页，再次访问首页会被拦截。
