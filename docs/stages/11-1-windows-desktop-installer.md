# 阶段 11.1：制作可直接安装使用的 Windows 桌面软件

## 目标

让普通朋友不必理解前后端，也不必打开两个命令行窗口：拿到一个安装包，安装后双击桌面“万事屋”即可使用。

## 架构

- Electron 提供独立桌面窗口，隐藏系统菜单，不开放 Node 集成。
- PyInstaller 将 FastAPI、SQLAlchemy、Alembic、网页正文提取和 Python 运行时打包。
- FastAPI 在同源地址托管前端构建页面与 `/api/v1`，避免跨域和额外前端进程。
- 启动时自动迁移 SQLite；数据与 JWT 密钥保存在用户数据目录，升级或重启不清空。
- 后端只监听 `127.0.0.1`。桌面程序优先使用固定端口保持登录状态，端口被占用时选择空闲端口。
- 单实例、启动健康检查、后台日志、启动失败重试、退出清理后端、外部链接交给默认浏览器。
- NSIS 生成每用户安装包，创建桌面和开始菜单快捷方式，无需管理员安装到系统目录。

## 构建中实际解决的问题

1. **打包后端迁移时找不到 app**：字符串加载使 PyInstaller 无法收集业务模块；改为在环境变量准备后显式导入应用对象，再运行迁移和服务器。
2. **替换旧构建目录被安全策略中止**：保留旧构建作为备份，在全新输出目录重新收集，没有强制删除旧文件。
3. **Electron Windows 二进制下载失败**：改用 npmmirror 镜像和 D 盘缓存，构建脚本同步保留镜像配置。
4. **桌面主进程 API 为 undefined**：当前开发环境的 `ELECTRON_RUN_AS_NODE=1` 强制 Node 模式；桌面测试与构建时清除该变量。
5. **GPU 兼容性警告**：应用不需要复杂图形加速，关闭硬件加速后复测无警告。
6. **运行资源遗漏风险**：显式打包数据库迁移、五份 AI 提示词、前端构建和 Trafilatura 资源，并检查产物中的实际文件。

## 验证

- 静态托管与账号相关 12 项专项测试通过；后端全量 **341 项测试**通过，Ruff 和 Electron 主进程语法检查通过。
- 独立打包后端在全新数据目录完成自动迁移、账号注册；关闭重启后原账号登录成功。
- Electron 源码模式、`win-unpacked` 打包模式均输出 `WANSHIWU_DESKTOP_SMOKE_OK`。
- NSIS 安装包已实际安装到全新目录，安装后的 `WanShiWu.exe --smoke-test` 启动成功。
- 前端 TypeScript、Vite、PWA 构建单独复跑通过；仅有既有包体积提示。
- 最终安装包：`desktop/release/万事屋-Windows-1.0.0-安装包.exe`，约 160 MB。

## 使用与边界

- 朋友只需要安装包，不需要源码、Python、Node.js 或命令行。
- 普通功能本机可用；AI 和网页抓取需要网络，模型服务可能收费。
- 数据只存在当前电脑，不提供云同步。退出软件后复制 `%LOCALAPPDATA%\WanShiWu\data` 可备份。
- 当前未配置商业代码签名，Windows 可能提示未知发布者；公开分发建议后续签名。
- 本轮验收环境为 Windows 11 x64，未宣称 macOS、Linux、Windows 32 位或所有朋友电脑均已验证。
