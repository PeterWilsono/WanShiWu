# 阶段 3.8：AI 意图评测集与手动评测工具

## 为什么需要评测

“看起来能理解”不能证明 AI 入口可靠。修改一句 Prompt 或换一个模型后，需要同一批输入和数字指标判断效果究竟提升还是退化。

本任务只建立评测资产并离线验证，**没有调用真实模型，也没有产生真实准确率**。

## 数据集

`backend/evals/cases.jsonl` 共 36 条，覆盖全部 8 种工具：

- 7 条信息不足、必须追问的用例；
- 2 条一句话包含多个动作的用例；
- 明天、下周、周几、保质期等相对时间；
- 整数/小数金额、收入支出分类、发生时间；
- 食材数量、单位、存放方式与过期日；
- 链接收藏、旅行目的地、预算和偏好。

用例尽量采用“早饭打车花了28块5”“明天那个事帮我弄一下”等自然表达，而非全部是正式书面语。

## 评测脚本

`backend/evals/run_intent_eval.py` 固定当前时间为 2026-10-30 09:00（上海，周五），直接复用真实 `parse_text → LLMClient → 工具校验` 流程，避免评测与线上逻辑各写一套。

必须显式传 `--confirm-real-api` 才会访问模型，并检查密钥是否仍为占位值。脚本使用独立内存数据库，不触碰开发数据，不执行 confirm。

输出指标：意图准确率、字段准确率、追问召回率、平均耗时、Prompt/Completion/总 token 和失败用例数；每条结果保留工具与字段错误，便于定位问题。

## 比较规则

标题允许包含式宽松匹配；时间按同一时刻精确比较；金额和数量用 Decimal；多动作按顺序逐项比较。具体“下周”“一个月”等约定和运行命令记录在 `docs/eval_log.md`，真实报告 JSON 已加入 Git 忽略。

## 验证结果

3 个离线测试验证数据规模、ID 唯一、工具覆盖、追问数量、期望字段合法性及多动作/错误字段比较。脚本 `--help` 入口可用。完整后端回归和 Ruff 检查见本次提交汇报。

下一步需由用户配置真实模型密钥后手动运行评测，把真实指标追加到 `docs/eval_log.md`；不能用离线测试结果替代模型准确率。
