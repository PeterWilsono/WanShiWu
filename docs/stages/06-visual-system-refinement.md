# 阶段 6：全站视觉系统与月历时区修正

## 目标

在不改变既有业务接口和操作流程的前提下，把原本偏组件库默认样式的页面，重塑为统一、克制且有辨识度的“东方生活手帖”。重点不是堆砌装饰，而是让字体排印、留白、层级、色彩、动效和移动端体验形成一套可复用规则。

## 视觉与交互设计

- **色彩**：暖纸色作为页面底色，深墨绿承担主要文字和主行动，朱砂色用于品牌印记与重点操作，金色用于提示和辅助数据。
- **字体**：标题使用宋体组合，正文使用系统无衬线字体；通过字号、字重和行距建立层级，不依赖外来字体下载。
- **组件**：新增统一应用头部和线性 SVG 图标；首页、登录页及各管理页共享卡片、按钮、表单、空状态与反馈样式。
- **细节**：采用细线、留白、轻微纸张层次和不对称圆角；动效以短距离位移与透明度变化为主，并尊重系统的“减少动态效果”设置。
- **响应式**：桌面端突出内容节奏，移动端压缩非关键留白、提供可展开导航；390px 验收宽度下没有横向溢出。
- **业务可读性**：分类不再直接显示 `food` 等内部标识，改为中文分类名和矢量图标；食材数量只在展示层去除末尾无意义的零，不改变接口的十进制精度。

## 月历时区问题

真实数据验收发现，`2026-11-01T15:00:00+08:00` 的日程在月历中显示成了 `07:00`。后端返回的 UTC 时间 `2026-11-01T07:00:00Z` 本身正确，问题在 FullCalendar：仅设置 `timeZone: 'Asia/Shanghai'` 还不够，还需要命名时区适配器。

本次接入官方 `@fullcalendar/moment-timezone` 插件，由日历按照当前用户资料中的 IANA 时区解释 UTC 时间。没有手工加减 8 小时，因此其他用户时区及夏令时规则也不会被固定偏移掩盖。

## 主要文件

- `frontend/src/style.css`：全站设计变量与 Element Plus 基础样式统一。
- `frontend/src/components/AppHeader.vue`、`AppIcon.vue`、`CategoryIcon.vue`：导航与图标系统。
- `frontend/src/views/HomeView.vue`、`LoginView.vue`：首页与登录页的重点视觉重塑。
- 其余管理页：统一页面头部、卡片、表格、图表、月历和移动端规则。
- `frontend/index.html`、`vite.config.ts`、`public/pwa-icon.svg`：品牌色、页面元信息和 PWA 主题同步。
- `frontend/src/views/CalendarView.vue`：命名时区插件接入。

## 验证

- `npm run build`：vue-tsc、Vite 生产构建和 PWA 构建通过；只有大包体积提示，没有构建错误。
- 使用真实接口数据检查首页、登录、待办、月历、账目、统计、分类和食材页面。
- 检查 1440px 桌面与 390px 移动视口、移动导航、库存、临期、购物清单，无横向溢出、页面脚本错误或控制台错误。
- 月历复验结果：午后散步显示 `15:00`，待办显示 `18:00`，项目复盘显示 `10:00`，均与 Asia/Shanghai 用户输入一致。
- 分类图标与食材数量 `8`、`2`、`500`、`2.5` 的显示均已复验。

## 当前边界

这是一轮完整的视觉系统改造和浏览器抽样验收，不代表已获得任何设计奖项，也不替代真实设备上的可访问性与 PWA 安装验收。月历因时区数据产生独立较大懒加载包，后续如需优化首屏资源，可继续做更细的日期数据拆包。
