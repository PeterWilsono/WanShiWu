# 阶段 2.6：待办列表页与完整操作交互

## 这一步在做什么

本阶段把阶段 2.2～2.5 的后端接口和前端 API 封装变成真正可操作的页面：

```text
/todos
```

登录后可以从首页点击“管理待办”进入。页面支持：

- 查看待办列表与总条数；
- 按状态、标签筛选；
- 按截止时间、创建时间、优先级排序；
- 分页和修改每页条数；
- 新建与编辑待办；
- 完成普通或周期性待办；
- 删除待办；
- 查看加载、空数据、错误、逾期和完成状态。

## 页面如何组织

### 1. 筛选区

状态筛选直接对应后端的 `pending / done / cancelled`，不选择时查询全部状态。标签使用精确匹配，排序字段和方向由独立选择框控制。

点击“查询”会回到第 1 页，避免在第 5 页修改条件后，因为新结果不足 5 页而看到错误的空页面。“重置”恢复默认排序并清空筛选条件。

### 2. 卡片式待办列表

每条待办显示：

- 当前状态；
- 标题和备注；
- 截止时间；
- 优先级；
- 重复周期；
- 标签；
- 完成时间（如果已经完成）。

“已逾期”只出现在 `pending` 且截止时间早于当前时间的记录上。已完成或已取消的记录即使截止时间已过，也不会继续提示逾期。

使用卡片而非宽表格，是因为待办需要展示多种状态和较长备注，卡片在桌面与手机上都更容易重排。

### 3. 新建与编辑共用表单

对话框中的字段包括标题、备注、截止时间、优先级、周期和标签。

- 标题必填，最长 200 字；
- 空备注按 `null` 提交；
- 日期选择器得到 `Date`，提交前用 `toISOString()` 转为带时区的 UTC 字符串；
- 编辑时从已有待办复制表单值，不直接修改列表对象；
- 周期性待办必须设置截止时间，提前避免完成时无法生成下一次。

标签使用 Element Plus 的可创建多选框：输入新标签后按回车即可加入，已有标签可以直接选择。

## 需要理解的知识

### 1. 为什么编辑时要复制数据

`openEdit(todo)` 使用展开语法复制标签数组，并把其他字段重新赋给表单，而不是让表单直接绑定列表里的对象。

如果直接绑定，用户在对话框里输入时，即使还没点击保存，列表也会跟着变化；点击取消也无法自然恢复。复制后，只有后端保存成功并重新加载，列表才更新。

### 2. 前端日期和后端 UTC 如何衔接

后端存 UTC，浏览器表单使用本地 `Date`。提交时：

```ts
form.dueAt?.toISOString()
```

会生成带 `Z` 的 UTC ISO 字符串。展示时使用 `Intl.DateTimeFormat`，并传入当前用户的 `timezone`，因此不需要新增日期处理依赖。

### 3. 为什么操作后重新请求列表

新建、编辑、完成和删除都可能改变：

- 当前筛选结果；
- 排序顺序；
- 总条数；
- 周期待办的下一次记录。

重新请求列表能保证页面与数据库一致，比前端手动猜测每条记录如何移动更可靠。删除当前页最后一条时，如果不是第 1 页，会先退回上一页再加载。

### 4. 加载与操作状态为什么分开

- `loading` 控制整个列表区域；
- `submitting` 控制表单保存按钮；
- `actionId` 表示正在完成或删除哪一条记录。

分开管理可以避免保存表单时整个页面闪烁，也能防止对同一条记录重复操作。

### 5. 确认框取消不是业务错误

完成和删除都先弹出确认框。用户点击取消时直接结束，不显示错误消息；只有真正的 API 失败才显示 `ApiError` 或兜底提示。

## 路由与构建

`/todos` 使用懒加载：

```ts
component: () => import('../views/TodoView.vue')
```

首次打开首页时不必下载待办页面代码；进入该路由时才加载对应 JS 和 CSS。路由仍设置 `requiresAuth`，沿用统一登录守卫。

## 如何验证

自动验证：

```bash
cd frontend
npm run build
```

本阶段 `vue-tsc` 类型检查和 Vite 生产构建均通过，待办页面已生成独立分包。

手动联调步骤：

1. 启动后端 `uvicorn app.main:app --reload` 和前端 `npm run dev`；
2. 登录后进入 `/todos`；
3. 新建普通待办，修改标题、优先级和标签；
4. 新建每日待办并完成，确认列表出现下一次记录；
5. 按状态、标签筛选并翻页；
6. 删除记录，确认它从列表消失；
7. 停止后端后点击查询，确认页面显示可理解的错误提示。

本次没有引入浏览器 E2E 测试框架，因此手动联调步骤已提供，但不宣称已经自动执行。
