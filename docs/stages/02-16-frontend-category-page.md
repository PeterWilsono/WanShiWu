# 阶段 2.16：分类管理页面

## 这一步做什么

新增 `/settings/categories` 页面，让默认分类和自定义分类真正可管理。它与 `/transactions` 记账页互相跳转，首页也增加了入口。

## 页面能做什么

- 用标签页分别查看支出和收入分类，并显示各自数量。
- 新建自定义分类，填写类型、名称和可选图标。
- 修改内置或自定义分类的名称与图标。
- 删除未被引用的自定义分类。
- 展示加载、空列表、请求失败和操作进行中的状态。

## 涉及的知识

- **内置与自定义**：首次注册时生成的分类带有 `is_default` 标记。内置分类可以改名，但删除按钮禁用。
- **历史引用保护**：前端不在本地统计分类是否被引用，因为当前页面没有完整历史数据。删除时由后端检查所有账目，包括软删除历史；若仍被引用，直接显示后端返回的“只能改名”原因。
- **类型不可变**：分类一旦创建，不能从支出改成收入，否则旧账目的“类型与分类一致”规则会被破坏。编辑对话框因此禁用类型选择。
- **页面级状态**：分类数据只在当前页面请求，没有放进 Pinia；全局 Store 继续只保存用户、Token 和全局设置。
- **错误边界**：加载失败与“没有分类”是不同状态。加载失败显示重试按钮，真正的空列表才显示新建引导。

## 文件职责

- `CategoryView.vue`：分类加载、收支标签页、卡片列表、删除确认与错误反馈。
- `CategoryFormDialog.vue`：新建和编辑表单、名称校验、API 调用。
- `router/index.ts`：注册需要登录的 `/settings/categories` 路由。
- `TransactionView.vue` 与 `HomeView.vue`：已有或新增分类管理入口。

## 如何验证

执行 `cd frontend && npm run build`，类型检查和生产构建通过，`CategoryView` 生成独立分包。

手动验收建议：新建支出分类并用于记账；尝试删除该分类，确认显示引用保护；改名后回到记账页检查分类摘要；新建一个未使用的收入分类并删除；内置分类的删除按钮应始终禁用。

本阶段未引入浏览器 E2E，不把构建通过表述为自动联调已通过。至此 LIFE-03 记账和 LIFE-04 分类管理的前后端手动功能均已接通，提醒与统计仍属于后续任务。
