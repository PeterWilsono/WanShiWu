# 阶段 2.10：日程页面与新建编辑交互

## 这一步在做什么

阶段 2.7～2.9 已经完成后端日程接口、前端类型和 API 封装。本阶段把这些能力组合成可以实际操作的页面：

- 页面地址：`/events`；
- 首页新增“管理日程”入口；
- 未登录访问时，沿用路由守卫跳转登录页；
- 支持按时间范围查询、分页、新建、编辑和软删除。

主要新增文件是 `frontend/src/views/EventView.vue`，同时修改了前端路由和首页。

## 页面包含哪些能力

### 1. 时间范围查询

页面首次打开时默认查询本月。时间范围选择器对应后端：

```text
range_start = 查询窗口开始
range_end   = 查询窗口结束
```

查询结果包括所有与窗口重叠的日程，而不只是开始时间在窗口内的日程。例如一场从上月末开始、本月初结束的旅行，也会出现在本月结果中。

点击“本月”会恢复当前月份；清空时间范围后点击“查询”，可以查询当前用户的全部有效日程。

### 2. 日程卡片

每条日程显示：

- 标题；
- 开始和结束时间；
- 全天标记；
- 地点和备注；
- 提前提醒设置；
- 已结束标记。

`end_at = null` 的日程只显示开始时间，表示单点日程。全天日程按日期展示，普通日程按日期和时分展示。

### 3. 新建与编辑

新建和编辑共用一个对话框，包含：

- 标题；
- 开始时间；
- 可选结束时间；
- 全天开关；
- 地点；
- 提前提醒分钟；
- 备注。

编辑时会把当前日程复制进表单，取消对话框不会修改列表中的原对象。保存时调用 `createEvent` 或 `updateEvent`，成功后重新请求列表，保证分页、总数和筛选结果与数据库一致。

### 4. 删除

删除前使用确认框，防止误点。删除成功后：

- 重新加载当前时间范围；
- 如果删除的是当前页最后一条且不在第一页，自动返回上一页；
- 后端只执行软删除，数据库原记录仍保留。

## 需要理解的知识

### 1. 日期选择器与 API 时间如何转换

Element Plus 的日期选择器在表单中使用 JavaScript `Date`，API 层使用 ISO 字符串。提交时明确执行：

```ts
start_at: form.startAt.toISOString()
```

`toISOString()` 会生成带 `Z` 的 UTC 时间，满足后端“必须带时区”的要求。

展示时使用：

```ts
new Intl.DateTimeFormat('zh-CN', {
  timeZone: userTimezone.value,
  // 年月日、时分等格式
}).format(new Date(value))
```

这样数据库、API 和页面各自承担清晰职责：数据库存 UTC，API 传 ISO 字符串，页面按用户时区展示。

### 2. 为什么新建后切换到新日程所在月份

如果用户正在看 10 月，却新建了 12 月的日程，仍然查询 10 月会导致新记录不可见，容易误以为保存失败。

因此新建成功后，页面把筛选窗口切换到新日程所在月份并回到第一页。编辑则保留原筛选窗口；如果日程被移出当前窗口，它会按筛选规则自然消失。

### 3. 前端校验与后端校验的关系

表单会提前检查：

- 标题必填且不超过 200 字；
- 开始时间必填；
- 结束时间不得早于开始时间；
- 地点最长 200 字；
- 提醒分钟为非负整数。

这些检查用于即时反馈，但不能替代后端校验。后端仍会验证字段、时区、时间顺序、用户权限和数据约束，防止绕过页面直接调用 API。

### 4. 为什么操作后重新加载而不是只改本地数组

新增、编辑或删除都会影响服务端数据。重新请求可以同时保证：

- 列表按 `start_at、id` 正确排序；
- 时间范围过滤准确；
- 总数和分页准确；
- 其他标签页或客户端产生的变化也能同步。

代价是多一次请求，但当前数据规模下，这比手动维护各种边界情况更可靠。

## 当前边界

- 本阶段是时间范围列表，不是 FullCalendar 日历视图；日历视图将在后续对应阶段实现。
- 页面可以保存和展示 `remind_before_min`，但 reminders 表与调度器尚未实现，所以到点站内通知还没有启用。表单中已明确提示，避免造成误解。
- 本阶段未引入浏览器 E2E 测试。类型检查与生产构建已通过，但不把构建通过宣称为人工或浏览器联调已通过。

## 手动联调建议

启动后端与前端后，可以依次验证：

1. 登录后从首页进入“管理日程”；
2. 新建本月普通日程，确认标题、时间和地点正确；
3. 新建跨月日程，确认它在与时间窗口重叠时出现；
4. 新建无结束时间的单点日程；
5. 编辑开始或结束时间，尝试提交结束早于开始的数据；
6. 清空结束时间、地点、提醒和备注后保存；
7. 删除日程，确认列表和总数更新；
8. 退出登录后直接访问 `/events`，确认被拦截。

这些步骤是验收指南，本阶段没有宣称已自动执行。
