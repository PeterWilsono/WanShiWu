# 阶段 21：AI 把“到点去做的事”落进待办

## 这次要解决什么

在 PC 版首页对 AI 说：

> 明天下午 3 点去踢球，买了 5 片面包到冰箱

面包能正确进库存，踢球却只出现在日历里，待办清单里没有。用户想的是“明天下午三点要去踢球”，这是自己要完成的一件事，应该在待办里能勾掉。

## 背景：待办和日程不是一回事

万事屋把“要完成的事”和“占时间的安排”分开存：

| | 待办 todos | 日程 events |
| --- | --- | --- |
| 语义 | 自己要去做、可以勾选完成 | 与他人约定、需要到场参加 |
| 时间 | 可选的截止时间 `due_at` | 必须的开始时间 `start_at` |
| 完成 | 能标记完成、可重复 | 没有“完成”状态 |
| 日历 | **会显示**（带截止时间的待办会画进日历） | 会显示 |

所以“踢球”如果落成待办，会同时出现在待办清单和日历；落成日程则只在日历，且永远勾不掉。原来的问题是 AI 一看到“下午三点”就选了日程。

## 改了什么

### 1. 意图提示词（`backend/app/llm/prompts/intent.txt`，版本 1.0.0 → 1.1.0）

新增两条规则和一组示例：

- 自己要去完成的一件事，**即使带明确时间也用 `create_todo`**，时间写进 `due_at`；
- 只有与他人约定、需要按时到场参加的会议、约见、就诊、面试、课程、婚礼、演出、航班车次才用 `create_event`；
- 示例直接覆盖这次的场景：“明天下午三点去踢球 → 待办”“明天下午三点约了牙医 → 日程”“周日下午四点在滨江公园跑步 → 待办，地点写进备注”。

### 2. 工具说明（`backend/app/llm/schemas.py`）

原来每个工具的说明只有“万事屋动作：create_todo；严格按参数 Schema 填写”，模型只能靠名字猜。现在每个工具都有一句人话，明确 `create_todo` 用来记“带时间的个人安排”、`create_event` **不会出现在待办清单**。

### 3. 评测集（`backend/evals/cases.jsonl`）

- 用例 33「周日下午四点在滨江公园跑步」的期望从日程改为待办；
- 新增「明天下午三点去踢球」「后天上午十点去银行办卡」两条待办用例；
- 保留「约了牙医」「开产品评审」「带猫打疫苗」为日程，确保不是把所有带时间的话都塞进待办。

### 4. 确认卡片的兜底按钮（`frontend/src/components/AssistantComposer.vue`）

模型仍判成日程时，草稿卡片下方会提示“日程只占时间，不会进入待办清单”，并提供 **改为待办**：

- 开始时间自动变成截止时间，地点写进备注（`地点：滨江球场`），提醒字段清空；
- 卡片标题、摘要一起变成“新建待办”；
- 提交时按目标类型**重新组装参数**，不会把 `start_at`、`location` 等日程字段带到待办请求里（后端禁止多余字段，否则会直接 422）。

## 怎么验证的

- 后端 358 项测试全部通过；新增 `tests/test_assistant_routing.py` 断言提示词规则、工具说明和评测集都覆盖这条边界。
- 真实页面（生产构建 + 本地后端）：用拦截的解析响应模拟“AI 判定为日程”，确认卡片出现提示，点“改为待办”后标题、截止时间（2026-11-11 15:00）、备注（地点：滨江球场）都正确，提交体只剩 `title / note / due_at / priority`。
- 真实确认接口：用转换后的参数调用 `/assistant/confirm`，返回 `todo:1`，再查 `/todos` 能看到“踢球”且状态为 `pending`，截止时间为 15:00。

## 还没验证的

真实模型的判断仍需要你自己的 API Key 实测。提示词和示例已经把边界写清楚，但不同服务商、不同模型的服从度不一样；这也是保留“改为待办”按钮的原因。

## 已经造成的数据

之前那条“踢球”是日程记录，本次不会自动改类型。可以在日历里删掉后重新说一遍，或在待办里手动补一条。
