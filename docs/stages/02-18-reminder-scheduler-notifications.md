# 阶段 2.18：提醒扫描与站内通知 API

## 这一步做什么

让 reminders 表中的到点提醒自动变成用户可以看到的通知，并提供未读查询和标记已读接口。

## 三部分如何配合

1. **service 扫描规则**：查找 `remind_at <= 当前 UTC 时间`、`fired_at IS NULL`、未软删除的提醒，写入 `fired_at`。
2. **APScheduler**：在应用进程中每分钟调用一次扫描，任务设置 `max_instances=1` 防止同一任务重叠，`coalesce=True` 合并进程暂停期间错过的多次执行。
3. **通知接口**：只查询已经写入 `fired_at` 的记录。未来提醒只是计划，不会提前变成通知。

```text
日程提醒计划 → 每分钟扫描 → fired_at 有值 → 前端查询到通知 → 用户标记 read_at
```

## 新增接口

- `GET /api/v1/notifications`：通知列表，支持 `unread=true`、分页。
- `POST /api/v1/notifications/{id}/read`：标记已读，重复调用保持幂等。

列表响应中的 `total` 是当前筛选结果总数，`unread_count` 始终是当前用户全部未读通知数，方便前端更新角标。

## 涉及的工程知识

- **依赖注入时间**：扫描函数可接收固定 `current_time`，测试不用真的等待一分钟，也不会因运行时刻不同而不稳定。
- **应用生命周期**：FastAPI 启动时启动调度器，关闭时释放线程。
- **独立数据库会话**：后台任务没有 HTTP 请求的 `get_db`，每次扫描自行创建并关闭 Session。
- **配置开关**：`SCHEDULER_ENABLED=true` 控制调度；测试启动前设为 false，避免后台线程写开发数据库。
- **权限边界**：其他用户、已删除、尚未触发的记录均不能通过已读接口访问，统一返回 404。

## 验证

新增 7 个测试场景，覆盖到点/未来/已触发/已删除、重复扫描、无时区时间、未读筛选、幂等已读、用户隔离、未登录、参数校验和每分钟调度配置。完整后端回归 **205 项全部通过**，Ruff 检查通过。

当前采用单后端进程，符合说明书模块化单体约定；如果未来同时启动多个进程，需要再加分布式锁或数据库原子抢占，避免重复触发。
