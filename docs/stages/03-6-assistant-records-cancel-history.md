# 阶段 3.6：AI 记录取消与历史查询

## 这一步做什么

新增两个记录管理接口：

- `GET /api/v1/assistant/records`：查询当前用户的解析历史；
- `POST /api/v1/assistant/records/{id}/cancel`：取消一条待确认记录。

它们让“暂不处理”不再只是前端收起卡片，而能真正结束后端的待确认生命周期。

## 历史查询

支持 `page`、`page_size` 和 `status` 筛选。状态只允许 pending / executed / cancelled / failed，非法值走统一 40001 校验响应。

结果按创建时间、ID 倒序返回，包含原始输入、意图、候选动作、状态、结果引用、失败原因、执行时间和审计时间。所有查询都带当前用户 ID 并过滤软删除，其他用户的数据不会混入总数或列表。

## 取消规则

只有 `pending` 可以取消。成功后状态改为 `cancelled`，不创建任何业务对象，也不写结果引用和执行时间。

- 不存在、已删除或其他用户的记录：404 / 40401；
- 已执行、已失败、已取消：409 / 40901；
- 未登录：401 / 40101。

因此取消操作不会因网络重试而重复执行，也不会把已经落库的业务数据撤销。

## 验证结果

新增 4 个专项测试，覆盖分页、状态筛选、用户隔离、取消成功、重复取消冲突、已执行冲突、未登录和非法筛选参数。完整后端回归 **238 项全部通过**，Ruff 检查与格式检查通过。
